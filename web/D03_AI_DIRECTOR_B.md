## Ограниченный первый результат

Рабочая очередь задач одного выбранного магазина в принятом направлении B поверх существующих API. Экран показывает только факты ответа Director, состояние источников и разрешённые сервером действия. Демо-задачи и суммы D01 не используются. Новые внешние операции, backend-контракты, тарифы, membership и права не добавляются.

## Карта контрактов

| Элемент интерфейса | Фактический источник | Доступное действие | Ограничение |
|---|---|---|---|
| Выбранный магазин и роль | `GET /api/stores`: `stores`, `workspaces.role`, `can_manage_stores` | Смена через существующий `mai:store-changed` | Director работает только с одним `store_id`; данные предыдущего магазина надо очистить до нового запроса |
| Режим, время расчёта, сводка | `GET /api/director?store_id=…`: `mode`, `generated_at`, `summary` | Обновить факты | Ответ относится только к возвращённому `store_id`; поздние и отменённые ответы нельзя применять |
| Здоровье источников | тот же ответ: `sources[]`, сформированный из сохранённых WB snapshots и freshness policy | Открыть соответствующий рабочий раздел; для allowlisted источников запросить read-only sync | `missing`, `stale`, `incomplete`, `error` показываются явно; прогнозом не заменяются |
| Очередь задач | `actions[]` из rules-based `director_service` и сохранённых `DirectorAction` | Открыть `href`; принять/отклонить; для `can_execute + read_sync` обновить источник | Максимум 10; денежный эффект только из `observed_effect_kopecks`, `null` = «не рассчитано» |
| Принять / отклонить | `PATCH /api/director/actions/{id}` | `approve` или `reject` | Только owner/admin; решение append-only; внешнее исполнение не начинается |
| Обновить источник | `POST /api/director/actions/{id}/execute` | Поставить allowlisted read-only sync в очередь | Только owner/admin; только `execution_type=read_sync`; WB не изменяется |
| Измерить | `POST /api/director/actions/{id}/measure` | Сравнить сохранённую baseline со свежей метрикой | Только owner/admin; нужны совместимая метрика и актуальные обязательные источники |
| STOP | `control` из GET; `PATCH /api/director/control` | Остановить; возобновить с фразой `ВОЗОБНОВИТЬ TROVENDI` | Только owner/admin; STOP блокирует внешние записи, но сохраняет чтение и диагностику; уже принятый провайдером запрос не отменяется |
| Ранее принятые действия | `tracked_actions[]` | Повторное измерение при наличии метрики | Только текущий магазин; максимум 10 вне текущего run |
| Аудит | `audit[]` | Только просмотр | Последние 20 событий текущего магазина |

## Подтверждённый API-пробел

Director API не возвращает статус billing read-only и не объявляет его частью guard для action/control endpoints. Первый результат может достоверно показать read-only по роли workspace из `/api/stores`, но не должен выдавать это за подписочный статус. Добавлять клиентскую имитацию billing gate или менять backend-контракт в D03 нельзя.

## Критерии приёмки первого результата

1. `/director` использует направление B и существующие `/api/stores` и `/api/director*`; D01-демо данные отсутствуют.
2. На экране одновременно присутствуют имя выбранного магазина, режим, фактическая очередь, источники и STOP именно этого магазина.
3. При смене магазина старые данные, уведомления и pending-состояния очищаются сразу; отменённый или поздний ответ старого `store_id` не применяется.
4. Loading, отсутствие магазина, empty queue, API error, `missing`, `stale`, `incomplete`, source `error`, role read-only и активный STOP имеют явные состояния.
5. Viewer не видит активных mutation controls. Owner/admin сохраняет существующие approve/reject, read-only sync, measure и STOP semantics.
6. Недоступное действие не получает выдуманного исполнителя: остаётся переход к фактическому `href` и явное объяснение ограничения.
7. STOP не отключает разрешённое чтение и диагностику и не обещает отмену уже отправленного внешнего запроса.
8. Изолированные fixtures/mock API проверяют смену магазина во время запроса, отсутствие данных, ошибку API/источника, недоступное действие, read-only и STOP.
9. Стили полностью ограничены корнем D03 Director и не меняют другие рабочие разделы; keyboard focus, reduced motion и mobile layout проверены.
10. Browser-приёмка 1440/1280/390 и remote CI/Vercel выполняются только после разрешённого preview; deployment во время лимита не запускается.

## Защита асинхронного контекста

Каждая смена выбранного магазина создаёт новое поколение клиентского контекста, даже если пользователь вернулся к магазину с тем же `store_id` по маршруту A → B → A. Каждая mutation внутри поколения получает отдельный идентификатор операции. Success, error, refresh и завершающие изменения busy/confirmation применяются только к актуальным идентификаторам. Игнорирование позднего ответа относится только к интерфейсу: оно не отменяет уже принятую сервером операцию и не запускает автоматический повтор.
